# Handoff: ログケース（Apache アクセスログ調査 Web UI）

## Overview

手元の PC で、案件ごとの Apache アクセスログ（`access_log` / `.gz`）を取り込み、**絞り込み → 目視 → 分類 → 集計 → CSV 書き出し** を回すための一人用ローカル Web ツールの画面設計。

要件定義書（`docs/00-全体.md` ほか 18 本）と基本設計書にもとづき、**画面構成・画面遷移・UI をゼロから再設計**したもの。既存実装（Cursor が生成したもの）は「一覧が 100 件で打ち切られてスクロールがつらい」「フィルタと集計の入力方法がぱっと見で分からない」という課題があったため、その 2 点を設計の中心に据えている。

この設計が解こうとした課題は 3 つ。

1. **「見えている行」と「対象行」の混同** — 要件では、一括更新・集計・CSV の対象はすべて「適用中フィルタの全一致行」であり、画面に見えている範囲ではない。ここを UI で明示しないと事故になる。
2. **絞る／見る／分類する／集計する の往復コスト** — 要件は「画面 2 種」だが、そのまま作ると集計のたびに行き来が発生する。調査の反復単位で画面を組み直す必要がある。
3. **時間バケット集計の操作性** — n 秒／n 分／n 時間で刻む集計は表計算では代替できない価値であり、このツールの主目的のひとつ。専用の操作系を与える。

## About the Design Files

**このバンドルの HTML / CSS / JSX は「デザインリファレンス」です。** 動く高忠実度プロトタイプで、意図した見た目と振る舞いを示すためのものであり、そのまま本番コードとして出荷するものではありません。

実装タスクは、**この HTML デザインを、対象コードベースの既存環境（React / Vue / Svelte / Flask + Jinja など）の作法・ライブラリ・命名に合わせて再構築する**ことです。

- 既存環境がある場合：その環境のコンポーネント、状態管理、スタイル手法（CSS Modules / Tailwind / SCSS 等）、テーブル部品、フォーム部品を使って作り直す。**このプロトタイプの CSS クラス名やファイル分割をそのまま持ち込まない。**
- 既存環境がない場合：基本設計が「Flask 1 プロセス + ループバック + HTML を返す」構成（`docs/LCH_B01-起動コマンド.md`）を前提としているので、Flask + Jinja + 素の JS（または軽量な React）が自然。ビルドチェーンを持ち込まない判断も妥当。
- プロトタイプは**クライアント側でダミーデータを生成**している。実装では、この README の「State Management」「Data contract」に沿ってサーバ API に置き換える。

### プロトタイプで簡略化している点（実装時に必ず本実装へ）

| 箇所 | プロトタイプ | 実装すべきこと |
| --- | --- | --- |
| ログデータ | 起動時にブラウザ内で決定論的に生成（`app/logdata.js`） | SQLite（案件ごとに 1 ファイル）から行IDカーソルで取得 |
| 一覧の読み込み | 全件をメモリに持った上で仮想スクロール | 続き取り API（直前の行IDより後を N 件）。**全件をメモリに載せない** |
| フィルタ適用 | クライアントで配列フィルタ | SQL の WHERE に変換。一致件数は COUNT |
| 集計 | クライアントで集計 | SQL の GROUP BY。時間バケットはログ TZ 上の区切りで丸める |
| 一括更新 | クライアントの state 更新 | 単一トランザクションで UPDATE |
| CSV | Blob ダウンロード | サーバがストリーミングで書き出し、保存先は利用者が選ぶ |
| 取り込み | 進行を擬似アニメーション | ストリーミングで進行を返す。1 ファイル 1 トランザクション、途中失敗はロールバック |
| 画面遷移 | hash（`#/case/{id}`） | サーバルーティング（`GET /`, `GET /cases/{案件公開識別子}`） |
| 確認ダイアログ | その場で続行 | メッセージ一覧（`docs/05-メッセージ一覧.md`）の W_* を確認として出す |

## Fidelity

**High-fidelity（hifi）**。最終的な色・書体・余白・罫線・状態がすべて決まっている。実装者はコードベース既存のライブラリとパターンを使いつつ、**見た目はこの設計にピクセル単位で寄せる**こと。

対象解像度は **1920 × 1080（ブラウザ全画面）**。最小幅 1180px を想定し、それ以下は横スクロールでよい（このツールは一人用・据え置き前提）。モバイル対応は不要。

## 設計判断（実装前に読むこと）

要件の「画面 2 種（案件一覧 / 案件の作業画面）」は**実装都合の分割**であり、UI としては再設計した。結論は「**案件一覧 + 案件作成 + 1 案件ワークスペース（4 タブ）**」。

### 1. 案件一覧（`GET /`）
案件を選ぶ／作る／消す。表は **54px 行**で、案件名・LogFormat 先頭・ファイル数・行数・最終取り込み日時を 1 行に並べる。行クリックでワークスペースへ。行末の `…` メニューに「開く／名称変更／削除」。削除は**案件名の再入力**を要求する（取り消せないため）。

### 2. 案件作成（ドロワー 640px）
LogFormat を貼ると、**確定する列（識別子・型・指定子）がその場で並ぶ**。さらに「この書式で 1 行を試す」でサンプル行を分割でき、行マッチ用正規表現も見える。登録後に LogFormat が変えられない仕様なので、**確定前に納得できる**ことを最優先した。プリセット（combined / common / vhost+応答時間 / XFF 付き）を用意。

### 3. 案件ワークスペース（`GET /cases/{id}`）
**左レール（検索条件）は常設・全タブ共通**。右側がタブ（一覧 / 集計 / 取り込み / 案件情報）。理由：調査の実体は「条件を変えながら一覧と集計を交互に見る」ことであり、条件が画面ごとにリセットされると使えない。タブを跨いでも条件と一致件数が保持される。

- **一覧タブ**：一致件数、適用中条件のチップ、CSV ボタン、高密度グリッド（行 30px）、複数行選択で下部に一括バー。
- **集計タブ**：グループ・時間バケット・集計値を上部に固定し、結果表を下に。表のみ（グラフなし）— 要件と「CSV に近い形で正確に読みたい」という回答に従う。アクセス数セルには**極薄の比率バー**だけ敷き、傾向を視線で拾えるようにした。
- **取り込みタブ**：左にドロップ領域と進行、右に取り込み済みファイル一覧（読んだ／入れた／捨てた／重複）と列構成。
- **案件情報タブ**：案件名・LogFormat・列定義（型・指定子・時間軸・未設定件数）、カスタム列の追加削除、保存した条件の一覧。**列定義はここでしか見られない**ので、調査中に「この列なんだっけ」を解消する場所として置いた。

### 「見えている行 ≠ 対象行」を UI で担保する仕組み
- 左レール最上部に一致件数を **27px の大きな数字**で常時表示（`12,483 / 12,483 行` の対比）。
- 一括設定は**モーダルで「フィルタ一致の N 行すべて／画面に見えている行だけではありません」を明示**してから実行。
- 一括バー（行選択時）は「選択した N 行」と明示し、レール側の一括（一致全行）と**別の操作であることを文言で区別**。
- 集計タブの実行ボタン下に「対象: フィルタ一致 N 行」を常時表示。

### フィルタ（条件の積み上げ）
- 条件は**カード 1 枚 = 1 条件**、列 → 演算子 → 値の 3 段。カード左に縦線と番号ノード、カード間に `AND` ラベル。積み上がっている構造が一目で分かる。
- **値入力は実データの出現値と件数をドロップダウンに出す**（`/admin/config.php  (28)` のように）。「何を入れたらいいか分からない」への直接の回答。
- 文字列の「複数選択（いずれか）」は**検索可能なチップ**で、選択済みは強調。値の意味を取り違えない。
- カード下に**日本語の条件サマリ**（`Status 等しい "404"` を AND で連ねたもの）を常時表示。
- **未適用の変更があると**レール下部に「未適用の変更があります」の帯が出て、適用ボタンが有効化される。適用前後が色でも分かる（カード左の 2px アクセント）。
- 保存した条件はレール内のリストから 1 クリックで呼び出し（即適用）。

### 一覧（100 件上限の解消）
- **仮想スクロール**：DOM は常に数十行。`12,483 行` でもスクロールは滑らか。
- 先頭 2 列（チェック・行ID）は横スクロールでも**固定**。`Request` は等幅のメソッド＋パスに分解、`Status` は色付きピル（2xx 緑 / 3xx 灰青 / 4xx 橙 / 5xx 赤）。
- カスタム列はヘッダーに `✎` を出し、**セルクリックでインライン編集**（Enter 確定 / Esc 取消 / 空で未設定）。
- 行ID クリックで**詳細ドロワー**（生ログ行、分割値の全項目、カスタム編集、前/次の行）。目視確認と分類を 1 か所で回せる。
- キーボード `j` / `k` / `PgUp` / `PgDn`。

### 集計（時間バケット）
- `使わない / 使用中` のトグル + **n + 単位（秒・分・時間）**。`10 分 ごと` のように読み下せる形で表示。
- 軸が無い案件ではトグルが無効化され、理由をツールチップに出す（`E_WRK_CMB01`）。
- 結果表はグループ列 → 時間バケット開始 → アクセス数 → 集計値の順（CSV と同じ列順）。最下部に合計行を sticky 表示。

### 7. 行詳細ドロワー（幅 600px）

- 生ログ行：等幅 10.5px、行間 1.7、地 `#F6F6F2`、`word-break: break-all`
- 分割値：`kv-tbl`。見出しに識別子 + 指定子（等幅 9px `#B0B5B7`）
- カスタム：`inp`（高さ 28px）。blur で確定、Enter で blur

### 8. 一括設定モーダル（幅 520px）

### 9. トースト（右下、幅 372px）

## Interactions & Behavior

### 画面遷移
```
（起動 LCH_B01）
  └→ 案件一覧 (GET /)
        ├→ 案件を作成（ドロワー）── 成功 ──→ その案件のワークスペース
        ├→ 行クリック ──→ ワークスペース (GET /cases/{案件公開識別子})
        ├→ 名称変更（モーダル）／削除（モーダル、案件名の再入力）
        └→ ワークスペース → パンくず「案件」で一覧へ
```

### フィルタ
1. `条件を追加` で空の条件カードが 1 枚増える。既定の列は未使用の先頭列、演算子は型の先頭。
2. 列を変えると演算子と値がリセットされる（型が変わるため）。
3. 値を入力すると、その列の**出現値候補**がドロップダウンに出る（件数降順、最大 60 件、絞り込み入力可）。
4. `複数選択（いずれか）` は検索 + チップのトグル。未選択なら一致 0 件。
5. 条件を 1 つでも変えると**未適用状態**になる（レール下部に帯、カード左に 2px アクセント、`条件を適用` が有効化）。
6. `条件を適用` で一致件数・一覧・サマリが更新され、一覧は先頭へ戻る。集計結果は破棄（条件が変わったため）。
7. `解除` で条件と適用状態を空にし、全件に戻す。
8. `いまの条件を保存` → 名前を入れて Enter か `保存`。同名は上書き確認（`W_WRK_BIZ03`）。
9. 保存済みをクリックすると**即適用**され、一覧タブへ移動。ゴミ箱で削除。

### 一覧
- スクロールは仮想化。`j` / `k` で 3 行送り、`PgUp` / `PgDn` で画面送り（入力中は無効）。
- ヘッダークリックでソート（同一列で asc ⇄ desc）。数値列は数値比較、他は `localeCompare('ja')`。
- チェックボックスは**表示中の行**を全選択（`indeterminate` 対応）。選択は条件適用でリセット。
- カスタムセルをクリックするとインライン編集。`Enter` 確定、`Esc` 取消、`blur` 確定。空文字は未設定（null）。
- 行ID クリックで詳細ドロワー。`前の行` / `次の行` は**現在の一致行の中**を辿る。
- 行選択中は下部に一括バー。`適用` で選択行だけ更新、`Esc`/閉じるで選択解除。

### 一括設定（レール下部の CTA）
- 一致 0 件のときは無効。
- モーダルで「一致全行」を明示 → 列と値を選ぶ → `実行する`。
- 値が空なら未設定に戻す。実行後にトーストで件数を出す（`S_WRK_OK01`）。

### 集計
- `集計を実行`：
  - グループもバケットも未選択 → エラー「グループ列か時間バケットを選んでください。」
  - バケット ON で時間軸なし → `E_WRK_CMB01`
  - バケット ON で n が 1 以上の整数でない → `E_WRK_RNG01`
- 実行中はボタンが `集計中…` に。完了後、グループ→バケットの順でソート。
- 結果が出ると CSV ボタンが有効化。ヘッダーに実行秒数を表示。
- 条件を変えると結果は破棄（古い集計を見せない）。

### 取り込み
1. ファイル選択 or ドラッグ&ドロップ。`access_log` で終わらない／`.gz` でない名前は `E_WRK_FMT01`。
2. 同名ファイルが既にあると `W_WRK_BIZ01`（プロトタイプは警告トーストで続行）。
3. `取り込む` で 1 ファイルずつ進行（%）。完了ごとに結果 4 値が積み上がる。
4. 全完了で `I_WRK_INF01` のトースト + 取り込み済み一覧に追記。
5. 途中失敗時はそのファイル分を確定しない（`E_WRK_SYS01`）。プロトタイプは常に成功。

### その他
- モーダル / ドロワーは `Esc` で閉じる。背面クリックでも閉じる。
- 削除確認は**案件名を入力するまで実行ボタンが無効**。
- カスタム列削除は `W_WRK_BIZ04` の確認モーダル（取り消せない旨を明記）。

### アニメーション
- ドロワー：`translateX(24px) → 0` + opacity 0→1、0.18s ease-out
- モーダル：`scale(0.985) → 1` + opacity、0.14s ease-out、`translate(-50%,-50%)` 基準
- トースト：`translateY(8px) → 0` + opacity、0.16s ease-out
- ボタン / 行ホバー：0.1s（背景・罫線・文字色）
- 進行バー：`width` 0.18s linear

## State Management

### 画面シェル
```ts
cases: Case[]                 // 案件一覧（サーバから取得）
caseId: string | null         // URL 由来。null なら一覧画面
toasts: Toast[]               // {kind, text, code}
```

### 案件ワークスペース（案件ごとに 1 つ）
```ts
tab: 'list' | 'agg' | 'ingest' | 'schema'

// フィルタ
conds: Condition[]            // 編集中の条件（未適用を含む）
applied: Condition[]          // 適用中の条件 = 一覧/集計/CSV/一括の対象
activeSaved: string | null    // 呼び出した保存条件名
// Condition = { id, field, op, value: string | string[] }
// 派生: dirty = JSON(conds) !== JSON(applied)

// 一覧
sel: Set<number>              // 選択中の行ID
sort: { key, dir } | null
editing: { rowId, key, value } | null

// 集計
aggCfg: {
  groups: string[]
  bucket: { on: boolean, n: string, unit: 'sec' | 'min' | 'hour' }
  metrics: { col: string, fn: 'count' | 'sum' | 'avg' }[]
}
aggResult: GroupRow[] | null
aggRunning: boolean
aggElapsed: number | null

// データ
rows: Row[]                   // 実装では「読み込み済みの範囲」のみ
customDefs: string[]
files: IngestFile[]
savedList: NamedFilter[]

// UI
detailId: number | null
bulkOpen: boolean
addColOpen: boolean
```

### 状態遷移
| トリガ | 遷移 |
| --- | --- |
| `条件を適用` | `applied ← conds`、`sort ← null`、`aggResult ← null`、`sel ← ∅`、一覧を先頭へ |
| `解除` | `conds ← []`、`applied ← []`、`activeSaved ← null`、`aggResult ← null` |
| 条件カード編集 | `conds` のみ更新（`applied` は据え置き → dirty） |
| 保存条件クリック | `conds = applied = その条件`、`activeSaved = name`、タブを一覧へ |
| セル編集確定 | `rows[i].custom[key] = value \|\| null`（1 行のみ） |
| 一括実行 | 一致全行（`applied` の結果）の `custom[key]` を更新、`sel ← ∅`、トースト |
| 行選択 | `sel` の add/remove。一括バーの表示は `sel.size > 0` |
| カスタム列追加 | `customDefs` に追加 + 全行の `custom` に null キーを生やす |
| カスタム列削除 | `customDefs` から除去 + 全行の値を削除 + `aggCfg` からも除去 + `aggResult ← null` |
| 集計実行 | `aggRunning ← true` → 結果 → `aggElapsed` |
| 取り込み完了 | `files` に追記、`rows` に新規行を追加（実装では再取得） |

### データ取得（実装時の API 契約案）

```
GET  /                                  → 案件一覧（名前, format先頭, ファイル数, 行数, 最終取り込み日時）
POST /cases                             → 作成（name, logFormat）／検証 E_CSE_*
PATCH /cases/{id}                       → 名称変更
DELETE /cases/{id}                      → 削除
GET  /cases/{id}                        → ワークスペース初期表示（案件, 列定義, カスタム定義, 取り込み済み, 保存条件）
POST /cases/{id}/ingest                 → 取り込み（multipart, 進行をストリーミング）
GET  /cases/{id}/rows?after={rowId}&limit=200&filter={...}&sort={...}
                                        → { rows, matchedCount, hasMore }
POST /cases/{id}/rows/{rowId}/custom    → 1 行更新
POST /cases/{id}/bulk                   → 一括更新（filter, field, value）→ { updated }
GET  /cases/{id}/count?filter={...}     → { count }
POST /cases/{id}/aggregate              → 集計（filter, groups, bucket, metrics）→ { groups, elapsedMs }
POST /cases/{id}/export/rows            → 一致行 CSV（保存先は利用者が選ぶ）
POST /cases/{id}/export/aggregate       → 集計結果 CSV
POST /cases/{id}/filters                → 保存／上書き（name, conds）
DELETE /cases/{id}/filters/{name}
POST /cases/{id}/custom-fields          → 追加／DELETE で削除
```

**重要**：`rows` の取得は**カーソル方式**（`after=行ID`）にすること。オフセット方式は数百万行で破綻する。`matchedCount` は一覧と別に COUNT で返し、一覧の取得件数と一致していることを画面で突合できるようにする。

### 実装の進め方（推奨順）
1. 案件一覧 + 案件作成（LogFormat パーサの本実装と接続）。ここで列定義が確定する流れを固める。
2. 取り込み（`.gz` 対応、重複判定、進行、結果 4 値）。
3. 一覧（カーソル方式の続き取り + 仮想スクロール + カスタムセル編集）。
4. フィルタ（条件 → SQL、一致件数、値候補の distinct 取得、保存条件）。
5. 集計（GROUP BY + 時間バケット、`Time` 未設定の除外）。
6. CSV 2 種（UTF-8 BOM / CRLF / RFC 4180 / 全件 / 失敗時に途中ファイルを残さない）。
7. 一括更新、カスタム列の追加削除。
8. メッセージ（`05-メッセージ一覧.md` のコードを画面に必ず出す）。
