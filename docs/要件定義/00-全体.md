# ログケース 要件定義書

## 1. 概要・目的・背景

### 1.1 概要

手元の PC で、案件ごとの Apache アクセスログを取り込み、フィルタ・分類・集計して調べる一人用ツール。

### 1.2 目的

次の 3 つを、同じ案件のデータに対して行う。

1. 機能別・時間別のアクセス数集計
2. 自分で条件を指定した不正アクセスの調査
3. 監査としての不審なアクセスの追跡

自動判定（ルール検知や異常検知）はしない。

### 1.3 背景

現状は、サーバからコピーした `access_log` を表計算に貼り、フィルタと集計をしている（対話で確認）。困っている点は次のとおり（対話）。

1. 行数に上限がある
2. 貼り付けや集計が重い、落ちる
3. 時・分・秒の任意単位での集計が表計算では苦手

利用者は自分一人。ログファイルは自分でサーバに入りコピーする。`LogFormat` も対象サーバの Apache 設定から自分でコピーする。

### 1.4 成功の定義

- 表計算の行数上限に相当する打ち切りを、一覧・集計・CSV に置かない
- 数百万件規模でも処理が落ちない（待ちは分単位まで許容。出典: 対話）
- 時・分・秒の任意の n 単位で時間集計できる
- 条件を指定して該当行と件数を見て、不正・不審の判断ができる

## 2. スコープ定義

### 2.1 開発範囲（対象）

- 案件の作成・名称変更・削除
- Apache `LogFormat` 文字列に基づくフィールド分割と型付け（文字列・数値・日時）
- `access_log` および `.gz` の取り込みと永続化
- フィルタ（名前付き保存・呼び出しを含む）
- カスタムフィールドの追加・削除、1 行編集、一括設定、未設定への戻し
- フィルタ後の集計（時間バケットを含む）
- フィルタ後の行 CSV、集計結果 CSV
- 自分の PC 上でブラウザから操作する画面（外への公開はしない）

### 2.2 対象外

- 複数人での同時利用
- ログのリアルタイム受信、サーバからの自動取得
- 機能名と URL の対応ルール
- 案件をまたいだ横断集計
- 自動検知
- 行単位の削除
- 本システムによるバックアップ／復元
- 画面・CSV のマスキング
- ログイン認証
- 定期バッチ取り込み
- 集計条件の名前付き保存（フィルタのみ保存する）

対象 OS は方式設計で Windows のみに決定（O-001 Closed）。

### 2.3 外部サービスの範囲

| サービス / システム        | 役割                      | 本プロジェクトでの責任分界        | 備考                                      |
| ------------------ | ----------------------- | -------------------- | --------------------------------------- |
| 対象 Web サーバ（Apache） | アクセスログと `LogFormat` の出所 | 先方（サーバ側）。本システムは接続しない | ファイルと文字列の入手は手動。詳細は [R06](R06-業務運用要件.md) |

### 2.4 手動運用の範囲

サーバへのログインとファイルコピー、Apache 設定からの `LogFormat` 入手、分類の判断、CSV 保存先の選択、データ消失時の取り直しと再分類。詳細は [R06-業務運用要件.md](R06-業務運用要件.md)。

## 9. 要件見直しサマリ

| 項目 | 旧（要件案） | 新（合意） | 理由 |
| ---- | ------------ | ---------- | ---- |
| フィールド型 | 文字列・数値 | 文字列・数値・日時 | Apache の `%t` と時間集計のため（対話） |
| 数値フィルタ | 空欄 | 未設定、等しい、等しくない、より大きい、以上、より小さい、以下 | 空欄を埋めた（対話） |
| CSV | 集計結果のみ | 集計結果に加え、フィルタ後の行も出せる | 機能要件案の追記と対話 |
| 不正アクセス | （目的として言及） | 自動判定しない。条件指定で該当行と件数を見る | 対話 |
| ログ形式 | 形式が複数／選択 | Apache。案件ごとに `LogFormat` 文字列を指定 | 対話 |
| カスタムフィールド一括 | 手動や一括 | フィルタ一致行へ同じ値。対応ルールは持たない。空で未設定に戻せる | 対話 |
| フィルタ再利用 | なし | 案件内で名前を付けて保存・呼び出し | 対話 |
| 案件名 | 新規時のみ | あとから変更可。`LogFormat` は変更不可 | 対話 |
| 削除 | 永続化 | 案件ごとだけ削除。ファイル単位・行単位では消さない | 対話 |
| 性能 | なし | 落ちなければ分単位の待ちは許容 | 対話 |
| バックアップ | なし | 機能として持たない。消失時はサーバから取り直し。分類結果は失ってよい | 対話 |
| 機密 | なし | 自分の PC 外に出さない。マスキングしない | 対話 |
| 対象 OS | なし → 未決 O-001 | Windows のみ（方式設計で閉じた） | 方式設計 |
| 方式（DB・言語等） | 設計メモに記載 | 本要件定義には書かない | 方式設計へ送る |
| 取り込み重複 | 同じファイル名は確認のうえ別行として足す | 改行を除いた 1 行の文字列が案件内で同一なら登録しない | 対話 |

## 10. 用語

| 用語 | 意味 |
| ---- | ---- |
| 利用者 | このツールを使う自分一人 |
| 案件 | 1 つの `LogFormat` と、そこに取り込むログのまとまり。調査の単位 |
| アクセスログデータ | 取り込んだログ 1 行（フィールドに分割済み） |
| フィールド | `LogFormat` から決まる項目。識別子は label またはヘッダー名 |
| カスタムフィールド | 利用者が案件に足す文字列項目（機能名、業務分類など） |
| 取り込み | ログファイルを読み、アクセスログデータとして永続化すること |
| 名前付きフィルタ | 案件内に保存したフィルタ条件の組み合わせ |
| 未設定 | 値が無い状態。数値の `-`（`%b` 以外）、日時が取れない `Time`、空にしたカスタムフィールド |
