# 一覧と一致行CSVの並び替え Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一覧タブと一致行CSVで、行ID順／Time昇順／Time降順を同じセッションの並びとして切り替えられるようにする。

**Architecture:** `fetch_rows` が並びとキーセットカーソル（行ID、Time 並びでは `(time_abs, row_id)`）を受け取る。画面は一覧ツールバーのセレクトから `POST /cases/<id>/sort` し、案件ごとにセッション `sort_by_case` へ残す。CSV も同じ `fetch_rows` をその並びで呼ぶ。OFFSET は使わない。

**Tech Stack:** Python 3.12、Flask、Jinja2、DuckDB、pytest。追加依存なし。

## Global Constraints

- 仕様の正は `docs/superpowers/specs/2026-10-27-list-sort-design.md`
- 並び内部値は `row_id` / `time_asc` / `time_desc`。初期値と未知値は `row_id`
- 画面ラベルは `行ID（取り込み順）` / `Time の昇順` / `Time の降順`
- Time が無い案件では Time 並びを出さず、セッションに残っていても `row_id` で読む
- `time_abs` の NULL と空は空文字。昇順の先頭、降順の末尾
- フィルタの適用・解除では並びをリセットしない。一覧は先頭から取り直す
- 新しいメッセージコードは足さない
- 集計・一括・取り込み・集計CSVは並びの影響を受けない
- Windows では `.\.venv\Scripts\python.exe -m pytest ...` を使う。`&&` は使わない
- コミットはユーザーが指示したときだけ。各 Task 末尾の Commit はスキップする

```python
def fetch_rows(
    conn: sqlite3.Connection,
    conditions: list[Condition],
    after_row_id: int,
    limit: int = PAGE_SIZE,
    sort: str = SORT_ROW_ID,
    after_time: str | None = None,
) -> list[dict]:
    where, params = _where(conditions)
    sort = normalize_sort(sort)
    time_key = "COALESCE(r.time_abs, '')"
    if sort == SORT_TIME_ASC:
        order = f"{time_key} ASC, r.row_id ASC"
        use_time_cursor = after_time is not None
        cursor_sql = f" AND ({time_key}, r.row_id) > (?, ?)" if use_time_cursor else ""
        cursor_params: list[Any] = (
            [after_time or "", after_row_id] if use_time_cursor else []
        )
    elif sort == SORT_TIME_DESC:
        order = f"{time_key} DESC, r.row_id DESC"
        use_time_cursor = after_time is not None
        cursor_sql = f" AND ({time_key}, r.row_id) < (?, ?)" if use_time_cursor else ""
        cursor_params = [after_time or "", after_row_id] if use_time_cursor else []
    else:
        order = "r.row_id ASC"
        cursor_sql = " AND r.row_id > ?"
        cursor_params = [after_row_id]
    sql = (
        f"SELECT r.row_id, r.source_filename, r.line_no, r.time_display, "
        f"{time_key} AS time_abs "
        f"FROM log_rows r WHERE {where}{cursor_sql} "
        f"ORDER BY {order} LIMIT ?"
    )
    rows = conn.execute(sql, [*params, *cursor_params, limit]).fetchall()
    # ... existing log_fields / values_by_row 組み立て ...
        item["row_id"] = row["row_id"]
        item["source_filename"] = row["source_filename"]
        item["line_no"] = row["line_no"]
        item["time_abs"] = row["time_abs"] or ""
        out.append(item)
    return out
```

既存の `WHERE r.row_id > ? AND {where}` は、`WHERE {where} AND r.row_id > ?` に変えても意味は同じ。Time 並びの先頭（`after_time is None`）では行IDカーソルを付けない。

空時刻テストの `conn.commit()` は `DuckConn.commit()` を呼ぶ。

def _session_sort(case_id: str) -> str:
    data = session.get("sort_by_case") or {}

def _set_case_sort(case_id: str, sort: str) -> None:
    data = dict(session.get("sort_by_case") or {})
    data[case_id] = normalize_sort(sort)

def _effective_sort(case_id: str, has_time_axis: bool) -> str:
