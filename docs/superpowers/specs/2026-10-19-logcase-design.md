# ログケース 設計

日付: 2026-10-19  
対象: 手元の PC で Apache アクセスログを取り込み、分類・集計・調査する一人用ツール

## 1. 目的

利用者がサーバから取得した `access_log`（または `.gz`）を案件単位で取り込み、次の 3 つを同じ画面で行う。

1. 機能別・時間別のアクセス数集計
2. 自分で条件を指定して不正アクセスを調べる
3. 監査として不審なアクセスを追う

自動判定（ルール検知や異常検知）はしない。条件を指定し、該当行と件数を見て判断する。

## 2. 利用者と範囲

- 利用者は自分一人。データも操作も手元の PC の中だけにする。
- 画面はブラウザで開き、接続先は localhost のみ。外には公開しない。ログインは置かない。
- 案件をまたいだ集計はしない。フィルタと集計は、開いている案件の中だけとする。
- 取り込んだログは削除せず残す。案件そのものを消すときだけ、その案件のデータを捨てる。

対象外:

- 複数人での同時利用
- ログのリアルタイム受信
- 機能名と URL の対応ルール
- 案件をまたいだ横断集計
- 自動検知

## 3. 構成

手元で 1 つのプロセスを起動し、そのプロセスが画面用の静的ファイルと API を返す。ブラウザは `http://127.0.0.1` だけを開く。

永続化は SQLite とする。案件ごとにファイルを 1 つ持つ。ジャーナルは WAL にする。ログ行、列定義、カスタムフィールドは同じファイルに置く。フィルタ、一括更新、集計、CSV はすべてそのデータベースに対して行う。

言語は Python 3 とする。取り込み（gzip を含む）、Apache の `LogFormat` 解釈、SQLite、localhost の HTTP を 1 プロセスに収める。画面の見た目は実装時に決め、出来上がったあとで直せる。

数十万件は問題にしない。1 日およそ 1 万件、年単位で数百万件を想定する。速く保つために次を守る。

- 取り込みは、1 件ずつ確定せず、まとめて 1 回のトランザクションで挿入する。
- 時刻、数値の等値・範囲、カスタムフィールドの等値には索引を張る。
- 一覧は `OFFSET` で飛ばさず、直前の行 ID より後を取る。
- 一括の値設定は、見えている行ではなく、フィルタに一致した行への更新 1 回にする。
- 文字列の「含む」「含まない」は、初期は通常の検索とする。体感が足りないときだけ全文検索用の索引を足す。

## 4. 案件

1 案件につき `LogFormat` は 1 つ。ログファイルは何個でも追加できる。

案件の新規作成では、案件名と Apache の `LogFormat` 文字列を入れる。列の並びはこの登録時に決まり、あとからファイルを足しても列は増えない。登録後に `LogFormat` は変えられない。変える場合は別案件にする。

案件の削除は確認のあと、SQLite ファイルごと消す。取り消せない。

## 5. 列

`LogFormat` の指定子 1 つが 1 列になる。修飾子（`>`、`<`、ステータスコードの制限）は列の識別子を変えない。`%>s` も識別子は `Status` である。

### 5.1 識別子

- 引数の無い指定子は、次の label を識別子にする。
- `%{User-Agent}i` のように引数がある指定子（Cookie、環境変数、リクエストヘッダー、レスポンスヘッダー、ノート）は、引数の名前を識別子にする。例: `User-Agent`。
- 同じ識別子が 2 つできる `LogFormat` は登録しない。
- `%b` と `%B` はどちらも `Bytes` だが、同じ書式に両方は来ない。来た場合は重複として登録しない。

| 指定子 | 識別子 | 型 |
| --- | --- | --- |
| `%a` | RequestIP | 文字列 |
| `%A` | ServerIP | 文字列 |
| `%B` | Bytes | 数値 |
| `%b` | Bytes | 数値 |
| `%{VAR}C` | VAR | 文字列 |
| `%D` | Duration | 数値 |
| `%{VAR}e` | VAR | 文字列 |
| `%f` | File | 文字列 |
| `%h` | RemoteHost | 文字列 |
| `%H` | Protocol | 文字列 |
| `%{VAR}i` | VAR | 文字列 |
| `%I` | ReceiveBytes | 数値 |
| `%k` | KeepAliveRequests | 数値 |
| `%l` | RemoteLogName | 文字列 |
| `%L` | LogId | 文字列 |
| `%m` | Method | 文字列 |
| `%{VAR}n` | VAR | 文字列 |
| `%{VAR}o` | VAR | 文字列 |
| `%O` | SendBytes | 数値 |
| `%p` | Port | 数値 |
| `%{canonical\|local\|remote}p` | Port | 数値 |
| `%P` | ProcessID | 数値 |
| `%{pid\|tid}P` | ProcessID | 数値 |
| `%{hextid}P` | ProcessID | 文字列 |
| `%q` | Query | 文字列 |
| `%r` | Request | 文字列 |
| `%R` | Handler | 文字列 |
| `%s` | Status | 数値 |
| `%S` | TransferBytes | 数値 |
| `%t` | Time | 日時 |
| `%{strftime}t` | Time | 日時 |
| `%{sec\|msec\|usec}t` | Time | 数値 |
| `%T` | Seconds | 数値 |
| `%{ms\|us\|s}T` | Seconds | 数値 |
| `%u` | RemoteUser | 文字列 |
| `%U` | URL | 文字列 |
| `%v` | VirtualHost | 文字列 |
| `%V` | ServerName | 文字列 |
| `%X` | ConnectionStatus | 文字列 |
| `%{VAR}^ti` | VAR | 文字列 |
| `%{VAR}^to` | VAR | 文字列 |

型の根拠は Apache 2.4 の `mod_log_config` である。IP アドレスは文字列とする。日時は文字列でも数値でもない 3 つ目の型とする。

時間集計の軸は、型が日時の `Time` 列とする。これは `%t`、または strftime 形式の `%{format}t` から取る。`%{sec}t` / `%{msec}t` / `%{usec}t` も識別子は `Time` だが型は数値なので、`%t` と同時には登録できない。これらだけの案件では時間集計を使えない。日時型の `Time` が無い案件でも時間集計を使えない。

解釈できない指定子は登録しない。

### 5.2 値の保存

- 数値の `-` は未設定（NULL）とする。例外は `%b` だけで、Common Log Format の定義どおり `0` とする。
- 日時が取れない行の `Time` は未設定とする。
- 文字列の `-` は、文字としての `-` のまま保存する。
- `%{hextid}P` は 16 進の文字列とする。

## 6. 行

ログ 1 行が 1 レコードである。取り込み時に整数の行 ID を振る。案件の中で一意とし、ファイルを足しても振り直さない。どのファイルの何行目かも残す。

## 7. カスタムフィールド

案件の中で、利用者が列を足せる。例は機能名、業務分類、メモ、正規化 URL。型は文字列だけとする。名前は案件内で一意とし、ログの列の識別子とも重ねない。ログの列と同じ表に列として追加し、等値検索と集計用の索引を張る。未入力は未設定とする。

追加すると、一覧・フィルタ・集計の対象にすぐ出す。削除すると、その列の値も消える。削除は確認のあと取り消せない。

値の入れ方は 2 つ。

1. 一覧で 1 行ずつ、その行のカスタムフィールドだけ書き換える。ログ項目は読み取り専用。
2. いまのフィルタに一致した行すべてへ、同じ文字列を 1 回の更新で書く。画面に見えている行だけを対象にはしない。実行前に対象件数を出して確認する。

URL と機能名の対応ルールは持たない。

## 8. 取り込み

案件に `LogFormat` を登録したあと、`access_log` または `access_log.gz` を 1 つ以上指定する。`.gz` は展開しながら読む。利用者が先に解凍する必要はない。

行は Apache のトークン規則で分ける。時刻は角括弧、リクエスト行やヘッダーは引用符で囲まれた値として解釈する。空白区切りのリテラルはそのまま区切りにする。

解釈できた行だけを、1 回のトランザクションで挿入する。解釈できない行は捨て、ファイル全体は止めない。案件内に、改行を除いた 1 行の文字列がまったく同じ行が既にある場合は登録しない。読んだ行、入れた行、捨てた行、重複行の件数を取り込み結果に出す。

途中で失敗したときは、そのファイル分は確定せず、以前の取り込みだけが残る。

同じファイル名が既にあるときは、足す前に確認する。続行しても内容が同じ行は入れない。キャンセルすれば何も足さない。

## 9. フィルタ

条件は列ごと（カスタムフィールドを含む）。複数の列を指定したときは、すべてを満たす行だけが残る（AND）。1 つの列の複数選択は、その値のどれかに一致すれば残る（OR）。

文字列:

- 含む
- 含まない
- 始まる
- 始まらない
- 複数選択
- 以上
- 以下

以上と以下は辞書順で、大文字と小文字は区別する。

数値:

- 未設定
- 等しい
- 等しくない
- より大きい
- 以上
- より小さい
- 以下

日時:

- 未設定
- 等しい（秒まで一致）
- より前
- 以降
- より後
- 以前

数値や日時に変換できない値を条件に入れたときは実行しない。

適用すると一致件数を出す。解除すると全件に戻る。

## 10. 一覧

横スクロールできる表とする。列は行 ID、元ファイル名、ファイル内の行番号、ログ項目、カスタムフィールド。並びは行 ID 順。下へスクロールすると続きを読む。件数の上限は置かない。全件を一度にメモリへ載せない。

## 11. 集計

集計は、いまのフィルタに一致した行に対して行う。グループは、選んだ列（カスタムフィールドを含む）と、任意の時間バケット。時間バケットは日時型の `Time` を n 秒、n 分、n 時間で区切る。n は 1 以上の整数。区切りは、その行のログに書かれていたタイムゾーン上の時刻とする。`Time` が未設定の行は、時間バケットを使う集計から除く。日時型の `Time` が無い案件では時間バケットを選べない。

集計値:

- アクセス数は、グループに入った行数。常に出す。
- 文字列の個数と、数値の個数は、その列が未設定でない行数。
- 平均と合計は、未設定を除いた数値だけを使う。`%b` の `0` は未設定ではなく、合計に含める。

## 12. CSV

2 種類ある。どちらも UTF-8（BOM 付き）。書き出すのは画面に見えている行ではなく、対象の全件。件数で打ち切らない。進行状況を画面に出す。書き込みに失敗したときは、途中のファイルを残さず、画面に理由を出す。実行前に対象件数を出す。

1. 一致した行: いまのフィルタに一致したアクセスログ行。列は行 ID、元ファイル名、ファイル内の行番号、ログ項目、カスタムフィールド。
2. 集計結果: いま画面にある集計表。列はグループ化した項目、時間バケットの開始時刻（使う場合）、選んだ集計値。

## 13. 画面

画面は 2 つ。配置や見た目は実装時に決め、出来上がったあとで直せる。画面に出すものと操作の意味は次に固定する。

### 13.1 案件一覧

起動するとここを開く。案件を作る操作と、案件の表（案件名、`LogFormat` の先頭、ファイル数、行数、最終取り込み日時）がある。行をクリックすると作業画面へ移る。削除は確認のあと SQLite ファイルごと消す。

### 13.2 案件の作業画面

次の要素を持つ。並びは実装時に決めてよい。

- 案件情報: 案件名、登録済みの `LogFormat`、列の一覧（識別子と型）。カスタムフィールドの追加と削除。
- 取り込み: ファイル選択、進行状況、取り込み済みファイルの一覧。
- フィルタ: 列、演算子、値。適用と解除。一致件数。
- 一覧: 仮想スクロールの表。カスタムフィールドのセルだけ直接編集できる。
- 一括入力: カスタムフィールドと値。対象件数の確認。
- 集計: グループ列、時間バケット、数値の集計方法。結果表。
- CSV: 一致した行の書き出しと、集計結果の書き出し。

## 14. 失敗時

起動できない、案件のファイルが開けない、ディスクがいっぱい、といったときは、画面に理由を出す。途中まで書いたデータは残さない。

`LogFormat` の登録では、解釈できない指定子と、同じ識別子が 2 つある書式は受け付けない。理由は画面に出す。

## 15. 確認の観点

次を満たせば足りる。

- combined 形式と、ヘッダー付きの独自 `LogFormat` の両方で、列名と型がこの設計どおりに分かれる。
- `.gz` と非圧縮を同じ案件に足せる。
- 解釈できない行は捨て、件数に出る。解釈できた行は残る。
- フィルタ後の件数と一覧が一致する。一括入力は見えている行ではなく、その件数すべてが対象。
- 機能名でグループし、時間バケットを付けた集計が、同じ条件の行数と一致する。
- 一致した行の CSV と、集計結果の CSV がそれぞれ開ける。
- 一覧を下まで送っても、表示は続きだけを取り、全件を一度にメモリへ載せない。
