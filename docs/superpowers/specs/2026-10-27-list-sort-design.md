# 一覧と一致行CSVの並び替え

日付: 2026-10-27  
承認済み。一覧タブと一致行CSVに、行ID順／Time昇順／Time降順を切り替える。

## 1. 目的

取り込み順（行ID）のまま見るか、ログの Time で見るかを、同じ案件の一覧と CSV で揃えられるようにする。全件をメモリに載せない続き取りは維持する。

## 2. 並び

| 内部値 | 画面ラベル | 並び |
| ------ | ---------- | ---- |
| `row_id` | 行ID（取り込み順） | `row_id` 昇順。現状と同じ |
| `time_asc` | Time の昇順 | `time_abs` 昇順、同着は `line_no`（ファイル内行番号）昇順 |
| `time_desc` | Time の降順 | `time_abs` 降順、同着は `line_no` 降順 |

初期値は `row_id`。未知の値は `row_id` に戻す。新しいメッセージコードは足さない。

`time_abs` が NULL または空の行は、空文字と同じ位置にする（昇順の先頭、降順の末尾）。

Time が無い案件（時間軸フィールドが無い）では `time_asc` / `time_desc` を出さない。セッションに残っていても一覧・CSV は `row_id` で読む。

## 3. 保持

案件ごとにセッション `sort_by_case[case_id]` へ残す。フィルタの適用・解除、名前付きフィルタの呼び出しではリセットしない。タブを跨いでも残る。案件を開き直す（新しいブラウザセッション）と初期値に戻る。

## 4. 画面

一覧タブのツールバーに「並び」セレクトを置く。位置は一致件数の右、CSVボタンの左。変更したらすぐ `POST /cases/{case_id}/sort` し、一覧を先頭から取り直す。Time が無い案件ではセレクトを出さない。

集計タブ・取り込みタブ・案件情報タブ、集計CSV、一括設定、取り込みは並びの影響を受けない。

## 5. 続き取り

1回の件数は現状のまま。先頭はカーソルなし。

- `row_id`: 今どおり `GET /cases/{case_id}/more?after={最後の行ID}&tab=list`
- `time_asc` / `time_desc`: 同じ URL に `after_time={最後の行の time_abs}` と `after_line={最後の行の line_no}` を足す（URL エンコード）。比較は `(time_abs, line_no, row_id)` の組（同じ時刻・同じ行番号が複数ファイルにあるときの安定化に行IDを使う）。昇順は組がより後、降順は組がより前。`after_time` が無い続きは先頭から取り直す

欠け・重複を出さない。OFFSET は使わない。フッターは Time 並びのとき「続きは直前の行より後を取ります」。行ID並びのときの文言は今のまま。

## 6. エンジンと CSV

`fetch_rows` が並びとカーソルを受け取る。一覧と一致行CSV（`rows_csv_bytes` / `write_rows_csv`）はセッションの並びで同じ関数を呼ぶ。CSV の列順は変えない。集計CSVは変えない。

## 7. テスト

- 初期表示は行ID昇順
- Time 昇順は時刻、同着は行番号昇順。降順はその逆
- 「続き」で欠け・重複が無い（Time 並びを含む）
- 一致行CSVがセッションの並びと同じ
- Time が無い案件ではセレクトが無く、CSVも行ID順
- フィルタを変えても並びは残る
- 未知の並び値は行ID順

## 8. 文書

基本設計 WRK_D01 の一覧を、並びセレクトと Time 並びの続き取りに更新する。EXP_F01 は一致行の行順が一覧の並びと同じである旨を足す。メッセージ一覧は変えない。
