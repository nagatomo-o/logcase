# 取り込みファイル単位の削除

日付: 2026-10-24  
対象: 取り込み済みファイルを、案件ごとではなく元ファイル名単位で消す。

承認済み。スキーマは変えない。行は取り込み履歴 ID を持たないので、削除キーは元ファイル名とする。

## 1. 目的

誤って取り込んだファイルの行を、案件を作り直さずに取り除く。取り消せない。

## 2. 対象とキー

- 画面: 取り込みタブ「取り込み済みファイル」の各行に削除。
- キー: 元ファイル名（`log_rows.source_filename` / `import_files.source_filename`）。
- 同じ名前の取り込み履歴が複数あっても、どれを押しても同じ名前分をまとめて消す。
- 行単位の削除はしない。案件削除は今までどおり。

存在しないファイル名、空のファイル名は消さない。案件が無ければ既存の E_CSE_EXS01。

## 3. 消すもの / 残すもの

1 トランザクションで次を消す。途中失敗はロールバックし、既存の E_WRK_SYS01 を出す。

消す:

- その元ファイル名の `log_rows`
- それらの `row_id` の `log_values` と `custom_values`
- 同じ元ファイル名の `import_files` すべて

残す:

- 他の元ファイル名の行と履歴
- 名前付きフィルタ、カスタムフィールド定義、LogFormat
- 重複判定で入れなかった行。それらは先に入れた側のファイル名で残っている

`row_id` の欠番はそのまま。再取り込み時は既存どおり最大 `row_id`＋1。

## 4. 確認と成功

名前の再入力はしない。

1. 削除を押すと確認モーダルを出す（W_WRK_BIZ05）。
2. 文言: `{filename} の取り込み履歴と {row_count} 行を消します。取り消せません。`
3. `row_count` は確認時点の、その元ファイル名の行数。履歴件数は出さない。
4. キャンセルで閉じる。削除で POST する。
5. 成功は S_WRK_OK03（取り込みファイルを削除しました。）。取り込みタブへ戻る。

POST は `confirm=1` と元ファイル名を必須とする。`confirm` が無いときは確認画面を出し直す（一括設定と同じ）。確認と実行のあいだに行数が変わっても、実行は現時点のそのファイル名分を消す。

## 5. 実行後の画面

- 一覧・件数・取り込み履歴・タブのファイル数を取り直す。
- 集計キャッシュはその案件分を捨てる。
- 適用中フィルタと名前付きフィルタは触らない。一致件数は減ることがある。
- 前提文「取り込んだファイルは単位では消せません」をやめる。

## 6. メッセージ

| コード | 用途 | 文言 |
| ------ | ---- | ---- |
| W_WRK_BIZ05 | 確認 | `{filename} の取り込み履歴と {row_count} 行を消します。取り消せません。` |
| S_WRK_OK03 | 成功 | 取り込みファイルを削除しました。 |

新しい必須エラーは足さない。ファイル名が空、または履歴に無いときは何も消さず取り込みタブへ戻る（フラッシュなし）。

## 7. テスト

- 指定ファイル名の行・値・カスタム値・履歴が消え、他ファイル名は残る
- 同じ名前の履歴が 2 件あるとき、両方と、その名前の行が消える
- 他ファイルと内容が重複して入れなかった行は、先に入れた側のファイル名で残る
- 確認なし POST では消えない
- 無いファイル名では件数が変わらない
- 案件削除・取り込み・重複判定は回帰しない
