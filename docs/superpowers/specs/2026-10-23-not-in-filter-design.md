# 複数選択以外（not_in）

日付: 2026-10-23  
対象: 文字列フィルタに、複数選択の否定を足す。

承認済み。入力形式は既存の複数選択と同じ。案件データや保存済み条件の移行はしない。

## 1. 目的

指定した値のどれかと完全一致する行を除き、残りを残す。未設定の行も残す（複数選択の補集合）。

## 2. 演算子

| 項目 | 内容 |
| ---- | ---- |
| 画面ラベル | 複数選択以外 |
| 内部値 | `not_in` |
| 対象型 | 文字列のみ（ログ列・カスタム列） |
| 演算子の並び | 複数選択の直後 |

数値・日時には出さない。

## 3. 入力と保存

複数選択（`in`）と同じ。

- 値欄は 1 つのテキスト。カンマで区切る（例: `404,500`）。
- 前後空白の扱いは `in` と同じ（trim しない）。
- 適用時は `value.split(",")` で配列にしてセッションへ保存する。
- 再表示は配列をカンマで結合する。

既存の名前付きフィルタは触らない。`not_in` を含む条件は、保存すればその案件内で呼び出せる。

## 4. 一致規則

条件同士は AND のまま。1 条件の値リストは「そのどれでもない」。

行が残る条件:

- その列の値が未設定、または
- その列の値がリストのいずれとも完全一致しない

大文字小文字は区別する（`in` と同じ）。

空入力（値リストが空）:

- `in` は 0 件
- `not_in` は全件（`in` の補集合）

実装は `in` の EXISTS / `col IN (...)` の否定（`NOT EXISTS` で同じ IN 述語）とする。これで未設定行が残る。

## 5. 画面

値入力 UI は変えない（カンマ区切りのテキスト）。チップ化はしない。

条件サマリと一覧タブの適用中チップは、`in` と同じく件数表示にする（例: `User-Agent 複数選択以外 [3 件]`）。

新しいメッセージコードは足さない。不正な演算子は既存どおり無視する。

## 6. テスト

- `Request-Method` が `GET,HEAD` の `not_in` で、GET/HEAD 以外が残る
- カスタム文字列が未設定の行が `not_in` で残る
- 空入力の `not_in` は全件
- 文字列列の演算子一覧に `not_in` が出る。数値・日時には出ない
- 既存の `in` / 含む / AND は回帰しない

## 7. 文書

要件定義 R02（F-003 文字列演算子）と基本設計 WRK_D01（文字列演算子・複数選択の説明）に「複数選択以外」を追記する。メッセージ一覧は変更しない。
