# フィルタ検索と検索後遷移の高速化

日付: 2026-10-24  
対象: Time 範囲＋文字列完全一致の検索、検索後の画面遷移。  
承認済み。案件の作り直しはしない。

## 1. 目的

500万行規模で、次を速くする。

1. `Time` が指定時刻以降、かつ `Request-Method` が `POST` のような検索（一致件数と一覧先頭）
2. その条件を付けたあとのタブ切替・続き取りなど、作業画面の遷移

一致行 CSV は同じ検索 SQL を使う。ファイルへ書き出す時間は件数に比例して残す。進行表示は今回やらない。

## 2. 対象外

- 含む／含まない（`instr`）の高速化
- 集計の SQL 化
- 列の横持ち、FTS、DB 製品の変更
- Docker 経路の変更
- CSV 書き出し中の進行表示
- 秒数 SLO の新設（要件 R05 の「分単位まで可」は集計・CSV 用として残す）

## 3. 画面遷移（一致件数の使い回し）

作業画面の GET は、いま毎回「全件 COUNT」「一致 COUNT」「先頭 100 行」を走らせている。フィルタが変わっていないのに繰り返す。

セッションに案件ごとの件数を持つ。

| 項目 | 内容 |
| ---- | ---- |
| キー | 案件 ID ＋ いまのフィルタ仕様（適用中と同じ spec） |
| 値 | `total_row_count` と `match_count` |
| 捨てるとき | フィルタ適用／解除、名前付き呼び出し、取り込み、取り込みファイル削除、一括更新、カスタム列の追加削除 |

- キーが同じなら COUNT しない。表示はキャッシュの件数。
- 一覧タブと「続き」だけ `fetch_rows` する。集計・取り込み・案件情報タブでは行を取らない。
- フィルタを変えた直後の 1 回は COUNT する（検索そのもの）。

全件は取り込みのたびに変わるので、破棄条件に取り込みを含める。`COUNT(*)` をメタに永続化はしない（破棄で足りる）。

## 4. 検索 SQL

一致規則は変えない。

**日時**  
比較は現行どおり `substr(r.time_abs, 1, 19)`（秒まで、TZ を除く）。`substr` を外すと `isoformat()` のオフセットで「より後」の意味が変わるのでやらない。

索引（既存案件にも、無ければ作成）:

```sql
CREATE INDEX IF NOT EXISTS idx_log_rows_time_wall
  ON log_rows(substr(time_abs, 1, 19));
```

**文字列の等しい／等しくない／複数選択／複数選択以外**  
`EXISTS` 相関ではなく、値側から `row_id` を取る。

- 等しい: `r.row_id IN (SELECT v.row_id FROM log_values v WHERE v.identifier = ? AND v.str_value = ?)`
- 等しくない: 同じ副問い合わせの `NOT IN`（未設定は残る）
- 複数選択／複数選択以外: `str_value IN (...)` を同じ形で

カスタム列も同じ（`custom_values`）。含む／始まる／以上／以下は現行のまま。

数値の演算子は変えない（今回の検索に不要）。

既存の `idx_log_values_str (identifier, str_value)` を使う。

## 5. 接続時

`open_case`（と新規作成後の接続）で次を毎回出す。

- `PRAGMA journal_mode=WAL`
- `PRAGMA synchronous=NORMAL`
- `PRAGMA cache_size=-262144`（ページ換算で約 256MB。その PC のメモリ内）
- `PRAGMA temp_store=MEMORY`

索引が無い案件では、上記の `idx_log_rows_time_wall` を作り、そのあと `ANALYZE` を 1 回だけ走らせる。500万行案件では初回オープンが数分かかってよい。2 回目以降は作らない。

## 6. Export

`rows_csv_bytes` は、セッションに今のフィルタの `match_count` があれば COUNT を省略する。行の取り出しは 4 の SQL を使う。チャンク幅 5000 と UTF-8 BOM は変えない。

## 7. テスト

- `Time` 以降 ＋ `Request-Method` 等しい、の件数と行が現行と同じ
- 文字列 `ne` が未設定を残す（SQL 形を変えても）
- 日時の「より後」が TZ 付き `time_abs` で現行と同じ（`substr` 維持）
- 索引が無い DB を `open_case` すると `idx_log_rows_time_wall` ができる
- 同じフィルタで作業画面を 2 度開いても一致件数は同じ。2 度目は COUNT SQL が走らない（トレースで確認）
- 取り込みタブでは `log_rows` の一覧 SELECT が走らない
- 既存の含む／数値／CSV 見出しは回帰しない

## 8. 文書

方式 A07 に、フィルタ適用後の件数はセッションで使い回すこと、日時は `substr(time_abs,1,19)` の式索引、完全一致は値索引から `row_id` を取ること、を追記する。R05 の「分単位」は集計・CSV 書き出し向けとして残す。
