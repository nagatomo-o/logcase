# 取り込みの非同期化

日付: 2026-10-24  
対象: 複数ファイル取り込みでブラウザが待ち続けないようにする。

承認済み。解析エンジン（DuckDB / SQLite）は変えない。取り込みロジック（重複・破棄・派生列）は変えない。

## 1. 目的

複数ファイルを選んで取り込み開始したあと、ブラウザが応答待ちのまま固まらない。取り込みタブにすぐ戻り、ファイルごとの進捗が見える。取り込み中の検索や他操作は使えなくてよい。

## 2. 今との違い

今は `POST /cases/<case_id>/import` が全ファイルを順に入れてから 303 を返す。

変更後は、受け付けたファイルを一時領域に置き、裏スレッドで 1 ファイルずつ今と同じ `import_file` / `import_gzip_bytes` を実行する。POST はジョブ開始後すぐに取り込みタブへ戻る。

外部キュー、別プロセス、SSE、キャンセル、途中再開はしない。

## 3. ジョブ

プロセス内にジョブ表を持つ（`app.config`）。読み書きはロックで直列化する。永続化しない。

- キーは案件 ID。1 案件につき実行中ジョブは 1 つ。
- 他案件のジョブは同時に動かしてよい。案件ファイルが別だから。
- 状態: `queued` / `running` / `done` / `failed`（ファイル単位）。ジョブ全体は `running` か `finished`。
- 各ファイル: 元ファイル名、状態、完了時は read / inserted / discarded / duplicate、失敗時は E_WRK_SYS01。
- 受け付け時点で不正な拡張子、同名未確認、空選択はジョブに載せない（今と同じフラッシュ）。

実行中に同じ案件へ再取り込みしたら、ジョブは作らず W_WRK_BIZ06 を出して取り込みタブへ戻る。

## 4. 受け付けと一時ファイル

`POST /cases/<case_id>/import` の入力（複数選択、同名チェック）は今と同じ。

1. 案件が無ければ E_CSE_EXS01。
2. ファイルが無ければ E_WRK_REQ01。
3. 実行中ジョブがあれば W_WRK_BIZ06。
4. 各ファイル: 拡張子検査、同名検査（確認なしなら W_WRK_BIZ01 でスキップ）。
5. 残ったファイルが 0 ならジョブを始めない。
6. バイト列を `{data_dir}/.import_jobs/{case_id}/` に書く。表示名は今どおり `Path(filename).name`。ディスク上の名前は `{index}_{basename}` とし、同じ表示名が複数あっても上書きしない。
7. スレッドを開始して 303 で取り込みタブへ。フラッシュは I_WRK_INF02。

一時ファイルはジョブ終了時にその案件分を消す。起動時（`main` の変換のあと）に `{data_dir}/.import_jobs/` を空にする。残っていても再開しない。

## 5. ワーカーと接続

ワーカーはファイルを 1 つずつ、今と同じ関数で取り込む。1 ファイル 1 トランザクション。失敗したファイルはその分を確定しない（E_WRK_SYS01）。後続は続ける。

DuckDB / SQLite は案件ファイルを同時に開けない前提にする。

- ジョブ開始直前に `open_case` して取り込み履歴のスナップショットをメモリに取り、すぐ閉じる。
- ワーカーがジョブ中その案件の唯一の接続を持つ。
- 実行中、その案件では `open_case` する操作をしない。

実行中に止める操作（その案件）:

- 再取り込み、ファイル削除、フィルタ適用、一覧の続き、集計、カスタム編集、一括設定、CSV、案件名変更、案件削除

止め方: W_WRK_BIZ06 を出して取り込みタブへ戻す。案件一覧は、実行中の案件だけ DB を開かず、スナップショットの件数と「取り込み中」を出す。他案件は今どおり。

1 ファイル終わるたびに、その案件の集計キャッシュと件数キャッシュを捨てる（今と同じ）。

## 6. 進捗の見せ方

取り込みタブに進行パネルを出す。ドロップ欄の下、取り込み済み一覧の前。

- 「{done}/{total} 処理中: {filename}」
- ファイル行: 待ち / 処理中 / 完了（I_WRK_INF01 と同じ件数）/ 失敗（E_WRK_SYS01）
- 実行中は開始ボタンを使えなくする
- 実行中は 2 秒ごとに `GET /cases/<case_id>/import/status` を取りにいく。この GET は案件 ID の形式だけ見て、DB を開かない
- `job` が `finished` になったら、そのタブは 1 回だけ再読み込みする。再読み込み後の通常描画で取り込み済み一覧を DB から出す
- その再読み込みで I_WRK_INF03 を 1 回出す（ジョブに「通知済み」フラグを立て、二重に出さない）。ファイルごとの I_WRK_INF01 はフラッシュせずパネルに出す
- 案件が無ければ status は 404（本文 `{"job": null}`）

JSON の形:

```
{
  "job": "running" | "finished" | null,
  "done": 0,
  "total": 0,
  "current": "access_log.4" | null,
  "files": [
    {
      "name": "access_log",
      "status": "queued" | "running" | "done" | "failed",
      "read_count": 0,
      "inserted_count": 0,
      "discarded_count": 0,
      "duplicate_count": 0
    }
  ]
}
```

ジョブが無ければ `{"job": null}`。案件が無ければ既存どおり E_CSE_EXS01。

## 7. 再起動

プロセスが落ちたらメモリ上のジョブは消える。処理中だったファイルは今どおり未確定。一時ディレクトリは次の起動で捨てる。画面は通常の取り込みタブに戻る。

## 8. メッセージ

| コード | 用途 | 文言 |
| ------ | ---- | ---- |
| I_WRK_INF02 | 受け付け | 取り込みを開始しました。 |
| I_WRK_INF03 | 全ファイル終了 | 取り込みが終わりました。 |
| W_WRK_BIZ06 | 実行中の操作 | この案件は取り込み中です。 |

既存の E_WRK_REQ01 / E_WRK_FMT01 / W_WRK_BIZ01 / E_WRK_SYS01 / I_WRK_INF01 の文言は変えない。I_WRK_INF01 はパネル表示に使う。

## 9. テスト

既存の取り込みテストは、POST のあとジョブ完了を待ってからアサートする（スレッド join のヘルパ）。挙動（重複・破棄・派生列・同名）は変えない。

追加:

- POST が取り込み完了前に 303 を返す
- status が queued → running → done と進み、件数が出る
- 実行中の再取り込みは増えない
- 実行中のフィルタ POST は取り込みタブへ戻り、行は増えない
- 不正拡張子はジョブに載らない
- 同名未確認はジョブに載らない
- 1 ファイル失敗しても後続は入る
- 起動時クリーンで一時ディレクトリが消える

## 10. 対象外

- キャンセル、一時停止、リトライボタン
- ジョブのディスク永続化と再起動後の再開
- 進捗バーのパーセント（行数ベース）
- 取り込み中の検索・他タブ操作
- 取り込み SQL 自体の高速化（別件）
