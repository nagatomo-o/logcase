# A03 処理方式 方式設計書

親文書: [00-全体.md](00-全体.md)

## 1. 目的とスコープ

### 1.1 目的

同期／非同期、長い処理、失敗時の確定範囲を決める。

### 1.2 スコープ

- **対象**: リクエスト内同期、進行の返し方、同時実行、冪等の方針
- **対象外**: 個別 API、SQL、チャンクサイズ

### 1.3 依存する前提・制約

| 前提 / 制約 | 出典 |
|-------------|------|
| 定期バッチなし | 要件 R06 |
| 進行状況を画面に出す | 要件 R03 |
| 取り込み途中失敗はそのファイル分を確定しない | 要件 R01 / R02 |
| 待ちは分単位まで許容 | 要件 R05 |

## 2. 現状・課題（該当時）

該当なし。

## 3. 方式方針

すべての処理を HTTP リクエストの中で同期実行する。取り込み・集計・CSV もジョブキューに乗せず、同じ応答の中で進行を流す。同時に走らせる長い処理は 1 件まで（想定: 一人利用なので画面操作で自然に守る。排他の詳細は基本設計）。

## 4. 詳細設計（方式）

### 4.1 構成・配置

該当なし。ワーカープロセスは置かない。

### 4.2 方式の詳細

| 処理 | 方式 |
|------|------|
| 案件 CRUD、フィルタ適用、1 行編集 | 同期。短い応答 |
| 取り込み、一括更新、集計、CSV | 同期。同一応答で進行を流す |
| 定期バッチ | 置かない |
| リトライ | 自動リトライしない。利用者がやり直す |
| 取り込みの冪等 | 案件内でログ行内容（改行を除く 1 行）が一致する行は入れない。同じファイル名は確認のうえ続行できるが、内容が同じ行はスキップする |

ブラウザ切断・タイムアウトで中断しうる（デメリット承知）。中断時、そのファイル分は確定しない。

### 4.3 インターフェース／境界（方式レベル）

| 境界 | 相手 | 方式 | 備考 |
|------|------|------|------|
| 進行状況 | ブラウザ | 同一 HTTP 応答のストリーム相当 | 具体ヘッダは基本設計 |

## 5. 選定比較

| 候補 | 概要 | 利点 | 欠点 | 費用（構築／運用） | 結果 |
|------|------|------|------|-------------------|------|
| すべて同期 | リクエスト内で完了 | ジョブ表が不要 | 切断で中断 | 構築最小／追加プロセスなし | 採用（デメリット承知） |
| 長い処理だけ裏実行 | 同一プロセスのスレッド等 | 開き直しても状況を見られる | 進行状態の構築が増える | 構築中／プロセスは 1 | 却下 |
| 外部バッチ | スケジューラ | 定期実行に強い | 起動が 2 系統 | 構築大／運用大 | 却下 |

### 採用理由

ジョブ管理の構築費を払わない。分単位の待ちは要件上許容。切断中断はデメリット承知。

### 却下理由

裏実行は一人用の初回には過剰。外部バッチは「都度利用」と合わない。

## 6. 非機能への寄与

| 区分 | 本方式での対応 | 指標との関係 |
|------|----------------|--------------|
| 性能 | ブロッキングしてよい | 落ちなければ合格 |
| 可用性 | 失敗したらやり直す | SLA なし |
| 運用性 | キュー監視が不要 | 監視なし |

## 7. 運用・移行上の留意点

- 長い処理中はブラウザを開いたままにする
- 失敗したら同じファイルを取り直す（確定していないため）

## 8. 基本設計への引き継ぎ事項

| 項目 | 内容 | 基本設計での扱い |
|------|------|------------------|
| 進行の流し方 | 同一応答 | 実装手段（チャンク／フラッシュ） |
| 長い処理の排他 | 一人・想定 | 必要ならロック |
| 取り込みトランザクション | ファイル単位で確定 | トランザクション境界 |
| 行の重複 | ログ行内容が一意 | スキップし件数に出す |
