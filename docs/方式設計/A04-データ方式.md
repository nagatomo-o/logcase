# A04 データ方式 方式設計書

親文書: [00-全体.md](00-全体.md)

## 1. 目的とスコープ

### 1.1 目的

永続化の単位、製品、整合性、バックアップ方針を決める。

### 1.2 スコープ

- **対象**: 案件＝ SQLite 1 ファイル、論理的に持つ情報の種類、削除単位
- **対象外**: テーブル定義、索引の列、型の物理マッピング

### 1.3 依存する前提・制約

| 前提 / 制約 | 出典 |
|-------------|------|
| 手元に永続。案件単位で分かれる | 要件 R04 |
| 案件削除以外では消さない | 要件 F-010 |
| バックアップ機能なし | 要件 R07 |
| 数百万件、一括 UPDATE、集計 | 要件 R05 / R02 |

## 2. 現状・課題（該当時）

該当なし。

## 3. 方式方針

案件ごとに SQLite ファイルを 1 つ、リポジトリ横の `data/` に置く。案件削除はファイル削除。サーバ製品は置かない。キャッシュ層は置かない。

## 4. 詳細設計（方式）

### 4.1 構成・配置

`data/<案件識別>.sqlite`（ファイル名規則は基本設計）。1 プロセスが開いている案件ファイルに読み書きする。

ファイル内に持つ論理データ（物理表は基本設計）:

- 案件属性（名前、LogFormat、フィールド定義）
- 取り込みファイル情報
- アクセスログデータ（行）
- カスタムフィールド定義と値
- 名前付きフィルタ

### 4.2 方式の詳細

| 項目 | 方式 |
|------|------|
| 分割 | 案件＝ファイル。案件をまたぐ JOIN はしない（要件どおり横断集計なし） |
| 整合性 | 取り込みはファイル単位のトランザクション。途中失敗はそのファイル分を確定しない。案件内でログ行内容は一意 |
| 同時書き込み | 一人・同期なので、複数クライアントの同時更新は想定しない |
| ジャーナル | WAL を採用（想定）。取り込み中断時の復旧がしやすい。単一書き込みでもよい |
| バックアップ | 機能として持たない。OS のファイルコピーは利用者が任意で行うが、要件上は取り直しで足りる |
| キャッシュ | 置かない |

カスタムフィールド追加は、その案件ファイルのスキーマ変更になる。方式としては「案件ファイル内で列を足す」。DDL の詳細は基本設計。

### 4.3 インターフェース／境界（方式レベル）

| 境界 | 相手 | 方式 | 備考 |
|------|------|------|------|
| アプリ ↔ SQLite | 案件ファイル | sqlite3 | SQL は基本設計 |
| 案件一覧 | 複数ファイル | `data/` の列挙 | 一覧用の中央 DB は置かない（想定） |

## 5. 選定比較

| 候補 | 概要 | 利点 | 欠点 | 費用（構築／運用） | 結果 |
|------|------|------|------|-------------------|------|
| 案件ごと SQLite | ファイル 1 つ | 削除がファイル単位。標準ライブラリ。一括 UPDATE が単純 | 巨大な全件集計は遅くなる | 構築小／料金なし | 採用 |
| DuckDB | 列指向ファイル | 集計が速い | 行更新の手順と検証が増える | ライブラリ導入／料金なし | 却下 |
| PostgreSQL 手元 | サーバ 1 つ | 同時接続に強い | インストールと起動が乗る | 構築大／プロセス運用 | 却下 |

### 採用理由

一括設定と案件削除が要件の中心。追加サーバの運用費を払う理由がない。全件集計の遅さは分単位許容（R-003）。

### 却下理由

DuckDB は更新系の構築費が増える。PostgreSQL は都度起動の一人用に過剰。

## 6. 非機能への寄与

| 区分 | 本方式での対応 | 指標との関係 |
|------|----------------|--------------|
| 性能 | 索引は基本設計。製品は SQLite | 落ちない・打ち切りしない |
| 可用性 | ファイルが残っていれば再起動後も使える | バックアップ機能なし |
| 運用性 | 案件＝ファイル | 中身のダンプツール不要 |

## 7. 運用・移行上の留意点

- `data/` を消すと分類結果も失う（要件どおり取り直し）
- ファイルを別 PC へコピーすれば案件を移せるが、対象 OS は Windows のみ

## 8. 基本設計への引き継ぎ事項

| 項目 | 内容 | 基本設計での扱い |
|------|------|------------------|
| ファイル名 | 案件識別 | 命名規則 |
| スキーマ | 行・フィールド・カスタム・フィルタ | 論理／物理表 |
| 索引 | 時刻、数値、カスタム等値 | 索引設計 |
| WAL | 想定採用 | 接続時 PRAGMA |
| ログ行内容の一意 | 案件内 | 一意制約。重複は挿入しない |
