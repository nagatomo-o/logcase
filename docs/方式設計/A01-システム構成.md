## 1. 目的とスコープ

### 1.1 目的

動く単位、画面と処理の境界、環境の分け方を決める。

### 1.2 スコープ

- **対象**: 論理構成、物理（1 PC）、面の境界
- **対象外**: URL、画面項目、プロセス内モジュール分割の詳細

### 1.3 依存する前提・制約

| 前提 / 制約 | 出典 |
|-------------|------|
| ブラウザで操作。外へ公開しない | 要件 R03 / R05 |
| 都度起動。常時稼働しない | 要件 R05、対話 |
| 簡易 UI を同じ担当が作る | 方式議論 |

## 2. 現状・課題（該当時）

該当なし（新規）。

## 3. 方式方針

利用者の Windows PC 上で、Flask のプロセスを 1 つ起動する。そのプロセスが HTML を返し、取り込み・集計も行う。データは同一 PC の `data/`。Apache サーバとは接続しない。

## 4. 詳細設計（方式）

### 4.1 構成・配置

![論理構成図](assets/logical-architecture.svg)

| 要素 | 責務 |
|------|------|
| ブラウザ | 表示と操作。ループバックにだけ接続する |
| Flask プロセス | HTML 描画、LogFormat 解釈、取り込み、フィルタ、一括更新、集計、CSV |
| `data/` | 案件ごとの SQLite |
| Apache サーバ | 構成外。ログと LogFormat の入手元（手動） |

### 4.2 方式の詳細

- 起動: コマンドで 1 プロセス。使い終わったら止める
- 画面と API の別プロセスは持たない
- 環境の開発／本番の分離はしない（同じ PC）

### 4.3 インターフェース／境界（方式レベル）

| 境界 | 相手 | 方式 | 備考 |
|------|------|------|------|
| ブラウザ ↔ プロセス | 利用者 | HTTP（ループバック）、HTML | 詳細 URL は基本設計 |
| プロセス ↔ 案件ファイル | SQLite | ファイル I/O | A04 |
| プロセス ↔ 手元のログファイル | 利用者指定のパス | 読み取り | サーバからの取得は手動 |

## 5. 選定比較

| 候補 | 概要 | 利点 | 欠点 | 費用（構築／運用） | 結果 |
|------|------|------|------|-------------------|------|
| 同一プロセスが HTML | サーバサイド描画 | 起動が 1 つ。画面用リポジトリ不要 | 動的 UI が増えると HTML が煩雑 | 構築小／運用はプロセス 1 つ | 採用 |
| 同一プロセス + JSON API | 静的 JS と API | 仮想スクロールを足しやすい | 契約と画面の二重管理 | 構築中／運用は 1 プロセス | 却下 |
| 画面と API を別プロセス | 分離 | 将来の分離に強い | ポートが 2 つ | 構築大／運用大 | 却下 |
| 都度 1 プロセス起動 | 使い終わったら止める | 常駐メモリなし | URL を開く一手間 | 構築小／常駐費なし | 採用 |
| 常駐アプリ | トレイ等 | 開きやすい | インストーラが要る | 構築大／常駐の運用 | 却下 |

### 採用理由

一人・都度・簡易 UI なら、プロセスも描画も 1 つが最安。

### 却下理由

API 分離と常駐は、構築と運用の費用が一人用に見合わない。

## 6. 非機能への寄与

| 区分 | 本方式での対応 | 指標との関係 |
|------|----------------|--------------|
| 性能 | 処理は同一プロセス。件数打ち切りはしない | 分単位待ちは許容 |
| 可用性 | 冗長化しない | 起動中のみ |
| セキュリティ | 待ち受けは A06 | 外に出さない |
| 運用性 | 起動・停止がコマンド 1 系統 | 監視なし |

## 7. 運用・移行上の留意点

- プロセスを止めれば待ち受けは消える
- 移行対象の既存システムは無い

## 8. 基本設計への引き継ぎ事項

| 項目 | 内容 | 基本設計での扱い |
|------|------|------------------|
| 画面遷移 | 案件一覧と作業画面 | 画面設計 |
| 起動 URL | ループバックの固定ポート | ポート番号（想定 8765） |
