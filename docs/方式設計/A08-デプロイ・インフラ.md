# A08 デプロイ・インフラ 方式設計書

親文書: [00-全体.md](00-全体.md)

## 1. 目的とスコープ

### 1.1 目的

Windows 上への置き方、起動、データの位置、環境の範囲を決める。体制は自分で置く（社内構築相当）。構築に足る方式まで書く。作業手順書は書かない。

### 1.2 スコープ

- **対象**: OS、ソース配置、Docker Compose、venv、`data/`、ループバック固定ポート、CI なし
- **対象外**: インストーラ、IaC、クラウドサービス、具体コマンド列

### 1.3 依存する前提・制約

| 前提 / 制約 | 出典 |
|-------------|------|
| 自分の PC に自分で置く。委託しない | 方式議論 |
| Python + Flask | A02 |
| ループバックのみ | A06 |
| 要件 O-001 | 本観点で Windows のみに閉じた |

## 2. 現状・課題（該当時）

該当なし。

## 3. 方式方針

ソース一式をフォルダに置く。起動は Docker Compose を主とし、仮想環境のスクリプトも残す。ブラウザはループバックの固定ポートを開く。案件の SQLite はプロジェクト内 `data/`。クラウド・CI は置かない。

## 4. 詳細設計（方式）

### 4.1 構成・配置

| 要素 | 方式 |
|------|------|
| OS | Windows のみ |
| 実行 | Docker Compose（主）または CPython + venv |
| アプリ | ソース配置。exe 化しない |
| データ | `data/`（リポジトリ横）。gitignore する想定。Compose ではホストの `data/` をマウント |
| 待受 | ホスト公開はループバック。ポートは固定（番号は基本設計。想定 8765）。コンテナ内のみ `0.0.0.0` |
| 環境 | 開発＝本番。検証専用機なし |
| CI/CD | 置かない（想定。検証は手元） |
| シークレット | なし |
| コンテナ | Docker Compose。公開は `127.0.0.1:8765` |

### 4.2 方式の詳細

更新はソースを入れ替えてプロセスを起動し直す。サービス登録はしない。

マネージド（クラウド実行）は費用と「外に出さない」の両方で不採用。

### 4.3 インターフェース／境界（方式レベル）

| 境界 | 相手 | 方式 | 備考 |
|------|------|------|------|
| 起動 | 利用者 | Docker Compose（主）または起動スクリプト | 手順書は基本設計または README |
| ブラウザ | プロセス | `http://127.0.0.1:<固定ポート>/` | |

## 5. 選定比較

| 候補 | 概要 | 利点 | 欠点 | 費用（構築／運用） | 結果 |
|------|------|------|------|-------------------|------|
| ソース + venv + `data/` | 費用抑制 | 改修のたびに梱包しない。データがリポジトリ横 | Python が要る | 構築小／ランタイム維持 | 採用（併存） |
| Docker Compose + `data/` | 手元コンテナ | Python をホストに入れなくても起動できる。公開はループバック | Docker Desktop が要る | 構築小／ランタイム維持 | 採用（起動の主） |
| 単一 exe | 固め配布 | 実行機に Python 不要 | 警告・再梱包 | 構築中／改修のたびに梱包 | 却下 |
| pip パッケージ | プロファイルへ入れる | コマンドが短い | データが散る | 構築中／配置が分かりにくい | 却下 |
| Windows のみ | OS | 検証 1 系統 | 他 OS 不可 | 構築小／検証費小 | 採用 |
| 3 OS 同等 | 横断 | 持ち歩き | 検証 3 倍 | 構築大／検証大 | 却下 |
| クラウド実行 | マネージド | バックアップしやすい | 課金。公開面 | 構築大／従量 | 却下（非機能「外に出さない」） |

### 採用理由

一人で直しながら使うので、固め作業とクラウド課金を払わない。他 OS の検証費も初回は払わない。

### 却下理由

exe は Windows の警告対応が乗りやすい。pip は案件ファイルの所在が薄れる。クラウドは要件の非公開と費用が合わない。

## 6. 非機能への寄与

| 区分 | 本方式での対応 | 指標との関係 |
|------|----------------|--------------|
| セキュリティ | ループバック固定を起動に含める | A06 |
| 運用性 | サービス化しない | 都度起動 |
| その他 | クラウド料金ゼロ | 費用抑制 |

## 7. 運用・移行上の留意点

- Docker Desktop 未導入なら `scripts/run.ps1` は Python が要る（R-002）
- `data/` の削除は案件全損失。バックアップ機能は無い

## 8. 基本設計への引き継ぎ事項

| 項目 | 内容 | 基本設計での扱い |
|------|------|------------------|
| ポート | 固定 | 番号決定（想定 8765） |
| 起動 | Compose が主。venv スクリプトも残す | ファイル名と引数 |
| `data/` | 案件ファイル置き場 | ディレクトリ規約 |
| 依存 | Flask 等 | ロックファイル |
| README | 起動の概要 | 手順は最小 |
