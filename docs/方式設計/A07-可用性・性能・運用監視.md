# A07 可用性・性能・運用監視 方式設計書

親文書: [00-全体.md](00-全体.md)

## 1. 目的とスコープ

### 1.1 目的

冗長化、性能の置き方、監視の有無を決める。

### 1.2 スコープ

- **対象**: 単一プロセス、監視なし、性能目標の解釈
- **対象外**: 索引の列、EXPLAIN、SLO 数値の再定義

### 1.3 依存する前提・制約

| 前提 / 制約 | 出典 |
|-------------|------|
| 起動中だけ使えればよい | 要件 R05 |
| 監視・アラートなし | 要件 R07 |
| 数百万件でも落ちない。分単位待ちは可 | 要件 R05 |
| 一覧は全件を一度にメモリへ載せない | 要件 AC-008 |

## 2. 現状・課題（該当時）

該当なし。

## 3. 方式方針

可用性はプロセス 1 つ。冗長化・負荷分散・自動フェイルオーバは置かない。監視 SaaS もローカルログ基盤も置かない。失敗は画面と標準出力。性能は「落ちない」「打ち切らない」「続き取り」で満たす。秒数上限は置かない。

## 4. 詳細設計（方式）

### 4.1 構成・配置

該当なし（単一プロセスは A01）。

### 4.2 方式の詳細

| 項目 | 方式 |
|------|------|
| 冗長化 | なし |
| スケール | 垂直のみ（その PC の CPU／ディスク）。水平分割しない |
| 監視 | なし |
| ログ | 標準出力。ファイルローテーションなし |
| 障害 | 画面に理由。取り込みはファイル単位で未確定に戻す |
| 一覧の読み方 | 続き取り（キーセット相当）。OFFSET 連打はしない |
| 取り込み | まとめて 1 トランザクション（方式。件数の塊は基本設計） |
| フィルタ後の件数 | セッションに持ち、条件が同じあいだ COUNT しない |
| 日時フィルタ | `substr(time_abs,1,19)` の式索引 |
| 文字列の完全一致 | `log_values(identifier, str_value)` から `row_id` を取る |

### 4.3 インターフェース／境界（方式レベル）

| 境界 | 相手 | 方式 | 備考 |
|------|------|------|------|
| 障害通知 | 利用者 | 画面表示 | メール等は置かない |
| メトリクス | — | 該当なし | |

## 5. 選定比較

| 候補 | 概要 | 利点 | 欠点 | 費用（構築／運用） | 結果 |
|------|------|------|------|-------------------|------|
| 監視なし + 標準出力 | 費用抑制 | 料金ゼロ。要件一致 | コンソールを閉じると途中経過が残りにくい | 構築ゼロ／運用ゼロ | 採用（デメリット承知） |
| ローカルログファイル | ファイルに残す | 切断後も追える | ローテーション運用 | 構築小／ディスク | 却下 |
| 監視 SaaS | マネージド | 遠隔検知 | ログが外部に出る。課金 | 構築中／従量 | 却下 |

### 採用理由

都度起動・非公開なので監視の運用費を払わない。コンソール閉鎖はデメリット承知（同期処理の注意とセット）。

### 却下理由

SaaS は機密方針（PC 外に出さない）とも費用とも合わない。

## 6. 非機能への寄与

| 区分 | 本方式での対応 | 指標との関係 |
|------|----------------|--------------|
| 性能 | 続き取り、件数打ち切りなし | AC-008 / AC-010 |
| 可用性 | 単一プロセス | SLA なし |
| 運用性 | 監視ダッシュボードなし | R07 |

## 7. 運用・移行上の留意点

- ディスク不足は画面に出して停止（要件の失敗時）
- 性能劣化時は索引見直しまたは DuckDB 再検討（R-003）

## 8. 基本設計への引き継ぎ事項

| 項目 | 内容 | 基本設計での扱い |
|------|------|------------------|
| 続き取り | 行 ID より後 | 一覧クエリ |
| メモリ | 全件ロード禁止 | 実装制約 |
| 索引 | 時刻・数値範囲・カスタム等値 | A04 と合わせて設計 |
